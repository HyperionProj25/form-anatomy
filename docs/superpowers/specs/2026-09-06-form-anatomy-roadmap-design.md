# Form anatomy atlas: ship, restructure, and teach. Design

Date: 2026-09-06
Status: approved in conversation, pending written review
Repo: HyperionProj25/form-anatomy (public), hosted on GitHub Pages

## 1. Goal and audience

Form is a free, no-account 3D anatomy atlas for students. Primary audience is
undergraduate anatomy and physiology. The fascia content must go deeper than
undergrad: it is written so a student heading toward graduate fascia research
gets accurate, current, graded evidence with primary sources.

Guiding rule: knowledge transfer is king. Accuracy beats volume. Every factual
claim in the app is traceable to a source the build can verify. The existing
honest framing (fascial lines are teaching models; continuity does not prove
force transmission or treatment effect) is preserved everywhere.

## 3. Architecture

### 3.1 Static site

Plain Vite + React 19 + TypeScript. No server, no framework router, no
database. Output is `dist/` served by GitHub Pages at
`https://hyperionproj25.github.io/form-anatomy/`. Vite `base` is
`/form-anatomy/`; all asset URLs go through `import.meta.env.BASE_URL`.
`index.html` carries the static title, description, Open Graph and Twitter
meta, favicon, and theme color.

Tailwind stays (via `@tailwindcss/vite`) because `globals.css` imports it for
preflight; no utility classes are added.

Rejected alternatives: keep vinext + Cloudflare Worker (server for a page
with no server logic, beta framework, 100k req/day cap); react-three-fiber +
zustand + router (full viewer rewrite for no student-facing gain).

### 3.3 Viewer engine API

```ts
class AnatomyEngine {
  constructor(host: HTMLElement, handlers: {
    onProgress(fraction: number): void;
    onReady(): void;
    onError(message: string): void;
    onHover(id: string | null, x: number, y: number): void;
    onSelect(id: string): void;
  });
  load(url: string, dracoPath: string): void;
  ids(): string[];                              // catalog ids present in the mesh
  applyAppearance(styles: Map<string, PartStyle>): void;
  setView(preset: "front" | "back" | "side", animate?: boolean): Promise<void>;
  setCamera(c: CameraPose, animate?: boolean): Promise<void>;
  getCamera(): CameraPose;                      // {position, target}
  flyTo(id: string, opts?: { padding?: number; preset?: "front"|"back"|"side" }): Promise<void>;
  zoom(factor: number): void;
  drawPath(points: Vec3[], color: string): string; // returns path handle
  clearPaths(): void;
  onCameraChange(cb: (c: CameraPose) => void): () => void; // debounced
  dispose(): void;
}
type PartStyle = { visible: boolean; color: string; emissive: string;
                   emissiveIntensity: number; opacity: number };
```

Mesh-to-catalog mapping uses the GLB node name (`Parietal bone`,
`Parietal bone.001`), which is unique per node. The catalog stores it as
`node` and the engine builds `Map<node, Mesh>` then `Map<id, Mesh>`.

Camera animation: 900 ms ease-in-out lerp of position and target, cancelable
by user input. Existing raycast hit testing, hover tooltip, click-vs-drag
threshold, WebGL error fallback, disposal, and retry are kept.

### 3.4 App state and URL

```ts
type AppState = {
  mode: "muscles" | "bones" | "fascia";
  selected: string | null;          // catalog id
  hidden: string[];                 // catalog ids
  isolated: boolean;
  opacity: number;                  // 10..100
  view: "front" | "back" | "side" | "custom";
  camera: CameraPose | null;        // only when view === "custom"
  line: LineId;                     // sbl | sfl | ll | sl | bfl | ffl
  tour: { step: number; playing: boolean } | null;
  showPath: boolean;
  pinned: string[];                 // max 4
  filters: { region: Region | "all"; layer: "all"|"superficial"|"deep";
             side: "both"|"left"|"right"; search: string };
  modal: "about"|"guide"|"quiz"|"research"|null;
  quiz: QuizSession | null;
};
```

URL query parameters (all optional, omitted when default):

| param | meaning | example |
| --- | --- | --- |
| `m` | mode | `m=fascia` |
| `s` | selected id | `s=gastrocnemius-l` |
| `v` | view preset | `v=back` |
| `c` | custom camera, 6 numbers, 2 decimals | `c=0.1,0.3,2.4,0,0.2,0` |
| `l` | line id | `l=sl` |
| `t` | tour step (with `l`) | `t=3` |
| `h` | hidden ids, comma list, max 20 | `h=gastrocnemius-l,soleus-l` |
| `p` | pinned ids, comma list, max 4 | `p=biceps-brachii-l,triceps-brachii-l` |
| `r` | region filter | `r=hip-thigh` |
| `d` | layer filter | `d=deep` |
| `side` | side filter | `side=left` |
| `q` | quiz set to open | `q=line:sbl` |

`urlCodec.encode` drops defaults and unknown ids; `decode` ignores anything
that fails validation against the catalog. Sync uses `history.replaceState`
debounced 300 ms; the camera parameter is written only after a drag ends.
The detail panel and fascia panel each have a "Copy link" button that writes
`location.href` to the clipboard and shows a two-second toast.

### 3.5 Data catalog (generated, committed)

`scripts/build-catalog.mjs` reads `public/body.glb`, decodes each Draco
primitive with the `draco3d` npm decoder, and writes `src/data/catalog.json`:

```ts
type CatalogPart = {
  id: string;        // slug of name + side suffix: "gastrocnemius-l" | "-r" | none for midline
  node: string;      // GLB node name
  key: string;       // side-agnostic slug: "gastrocnemius"
  name: string;      // display name from nameDetail, surrounding parentheses stripped
  type: "muscle" | "bone" | "connective";
  side: "left" | "right" | "midline";
  region: Region;
  layer: "superficial" | "deep";
  centroid: [number, number, number];   // model space after recentering at bbox center
  bbox: [[number,number,number],[number,number,number]];
  wiki?: string;     // https://en.wikipedia.org/wiki/... only
};
type Region = "head-neck" | "back" | "thorax" | "abdomen-pelvis"
            | "shoulder-arm" | "forearm-hand" | "hip-thigh" | "leg-foot";
```

Side: centroid x greater than +0.008 model units is left (the model faces
+z, so +x is the subject's left), less than -0.008 is right, else midline.
Id collisions after the side suffix get a numeric suffix; a test asserts all
826 ids are unique and every id round-trips through the URL codec.

Region: `regions.ts` applies, in order, (1) manual overrides by key, (2) name
keyword rules (for example `intercostal` -> thorax, `gluteus` -> hip-thigh,
`erector|multifidus|trapezius|latissimus|rhomboid|splenius` -> back,
`interossei of hand|lumbrical|pollicis|digiti minimi of hand` ->
forearm-hand), then (3) geometry: y bands scaled to the model's height for
head-neck / trunk / hip / leg, with trunk-height parts whose |x| exceeds the
trunk half-width classed as shoulder-arm or forearm-hand by y. Every part
must receive a region; the test fails otherwise, and about 30 named spot
checks assert expected regions.

Layer: a curated deep-muscle keyword list in `regions.ts` (rotator cuff,
transversospinales, suboccipitals, scalenes, longus colli/capitis, internal
intercostals, transversus thoracis, diaphragm, transversus abdominis,
quadratus lumborum, internal oblique, iliacus, psoas, piriformis, obturators,
gemelli, quadratus femoris, vastus intermedius, adductor brevis/magnus,
popliteus, soleus, tibialis posterior, flexor digitorum/hallucis longus,
flexor digitorum profundus, flexor pollicis longus, pronator quadratus,
supinator, deep extensors of thumb and index, all interossei and lumbricals,
quadratus plantae). Everything else is superficial. The UI labels the filter
"Layer (approximate)". Bones and connective parts are `superficial` for
filtering purposes and the layer filter is hidden in bones mode.

The GLB is never modified; the catalog is derived. The script is
deterministic and re-runnable; its output is committed so CI builds need no
decoding step.

### 3.6 Facts pipeline (generated, committed)

`scripts/fetch-facts.mjs` fetches wikitext for each of the 227 unique
Wikipedia articles referenced by the catalog (`action=parse&prop=wikitext`,
one request per article, 250 ms apart, with a descriptive User-Agent). It
extracts the `Infobox muscle` fields `origin`, `insertion`, `action`,
`nerve`, `antagonist`, and for `Infobox bone` the `articulations` field,
strips wiki markup to plain text, and writes `src/data/facts.json`:

```ts
type Facts = Record<string /* wiki title */, {
  origin?: string; insertion?: string; action?: string; nerve?: string;
  antagonist?: string; articulations?: string;
  revision: number; retrieved: string;   // ISO date
}>;
```

Display precedence in the detail panel: curated lesson (`lessons.ts`) first,
then facts fields, then the model's own description (first 600 characters,
expandable). Every fact and description block carries "Text adapted from
Wikipedia, CC BY-SA 4.0" with a link to the article. Articles with no
infobox produce no facts entry and the panel simply omits those rows.

### 3.7 Fascial lines and evidence

`lines.ts` holds six lines: superficial back (sbl), superficial front (sfl),
lateral (ll), spiral (sl, new), back functional (bfl), front functional
(ffl). Each line:

```ts
type Line = {
  id: LineId; name: string; subtitle: string; color: string;
  view: "front"|"back"|"side";
  description: string; movement: string;
  overall: { grade: Grade; source: CitationId; note: string };
  path: Stop[];
};
type Stop = {
  name: string;
  key: string | null;        // catalog key; null when not modeled
  keys?: string[];           // extra keys highlighted with this stop
  note: string;              // one line, used as tour narration
  crosses?: boolean;         // functional/spiral lines: switch body side here
  transition?: { grade: Grade; source: CitationId; note: string }; // to next stop
  waypoint?: [number, number, number]; // path point when key is null
};
type Grade = "strong" | "moderate" | "none" | "not-reviewed";
```

Overall grades follow Wilke et al. 2016: strong for sbl, bfl, ffl; moderate
for sl and ll; none for sfl (no structural link between rectus femoris and
rectus abdominis). Per-transition grades are transcribed from that review's
tables during implementation; any transition the review did not assess is
`not-reviewed`. Grades render as a colored badge next to each hop in the
path list, with the note on hover/tap and the source linked.

Spiral line stops: splenius capitis and cervicis -> rhomboids (crosses) ->
serratus anterior -> external oblique -> internal oblique (crosses) ->
tensor fasciae latae -> tibialis anterior -> fibularis longus -> biceps
femoris -> sacrotuberous ligament (not modeled) -> erector spinae.

### 3.8 Research digest

`research.ts` holds citation records:

```ts
type Citation = {
  id: CitationId; authors: string; year: number; title: string;
  journal: string; pmid?: string; doi?: string; url?: string;
  kind: "systematic-review"|"scoping-review"|"meta-analysis"|"rct"
      | "cadaveric"|"in-vivo-imaging"|"narrative-review"|"consensus"|"reference";
  group: "what-fascia-is"|"continuity"|"force-transmission"|"sensory"|"clinical";
  summary: string;    // 2-4 plain-language sentences
  modelNote: string;  // what this means for the model on screen
};
```

Candidate set (each must pass verification; any that fails is dropped, never
patched by guessing):

- Wilke, Krause, Vogt, Banzer 2016, Arch Phys Med Rehabil, PMID 26281953 (systematic review)
- Krause, Wilke, Vogt, Banzer 2016, J Anat, PMID 27001027 (systematic review)
- Myofascial continuity: review of anatomical and functional evidence, J Bodyw Mov Ther 2025, PMID 41316622 (narrative review)
- Bordoni et al., Fascial Nomenclature: Update 2024, Cureus, PMID 38343702 (consensus)
- Stecco, Pratt, Nemetz, Schleip, Stecco, Theise 2025, J Anat, DOI 10.1111/joa.14212 (consensus)
- Adstrum, Hedley, Schleip, Stecco, Yucesoy 2017, Defining the fascial system, J Bodyw Mov Ther (consensus)
- Suarez-Rodriguez et al. 2022, Fascial innervation: a systematic review, Int J Mol Sci, PMID 35628484
- Evidence of in-vivo myofascial force transfer in humans: a systematic scoping review, 2022, PMID 36180147
- In vivo evidence of myofascial force transmission along the posterior spiral chain, PMC12867544 (in-vivo imaging)
- Wilke, Vogt, Niederer, Banzer 2017, remote stretching RCT, J Sports Sci (rct)
- Lin et al. 2026, remote myofascial manual therapy along the superficial back line, meta-analysis, DOI 10.1177/10538127261428186
- Huijing 2009, epimuscular myofascial force transmission historical review, J Biomech (narrative review)
- Quadriceps epimuscular transmission in passive conditions, J Biomech 2018 PMID 30477875 and Eur J Appl Physiol 2021 DOI 10.1007/s00421-021-04801-6 (in-vivo imaging; counter-evidence)
- Schleip et al. 2019, fascia is able to actively contract, Front Physiol (cadaveric/histology)
- Anatomy, Fascia, StatPearls NBK493232 (reference)
- OpenStax Anatomy and Physiology 2e (reference)

The digest modal groups entries by `group`, shows the kind badge, summary,
model note, and an outbound link. Lines and stops reference citations by id.

`scripts/verify-citations.mjs` resolves every PMID via NCBI E-utilities
esummary (title must be non-empty) and every DOI via `https://doi.org/`
(HTTP 200 or 30x). It exits non-zero on any failure. CI runs it before build.

### 3.9 Features

Region and depth browsing (library panel): the list groups by `key` and
shows each structure once with a small L/R control when bilateral; clicking
the name selects the right side by default, or the side chosen in the side
filter. Filters: region chips (8 + all), layer (all/superficial/deep, hidden
in bones mode), side (both/left/right). Search matches name and key.
Counts shown per filter state. Empty state suggests three names.

Guided tours (fascia panel): "Start tour" builds stops from the line's path.
Each step calls `flyTo` with the line's preset, sets `selected` to the stop's
part (or shows a "not separately modeled" card with the waypoint), shows the
note as narration and the transition grade to the next stop. Controls:
previous, next, play/pause (advance every 6 s), exit. Arrow keys work while
the panel has focus. `t` in the URL restores the step.

Draw the line (viewer): for each line, `paths.ts` builds ordered points per
body side from stop centroids (plus waypoints), switching side at `crosses`,
fits a CatmullRomCurve3, and draws a TubeGeometry (radius 0.006, 240
segments, MeshBasicMaterial in the line color, depthTest off, opacity 0.85,
renderOrder 10) plus a 0.012-radius pulse sphere moving along the curve every
4 s. "Show path" toggle defaults on. Caption under the legend: "Teaching path
drawn through structure centers. Not a fascial sheet."

Full muscle facts (detail panel): rows for origin, insertion, action,
innervation, antagonist when present; curated lesson block when present;
description expander; Wikipedia attribution; "Read anatomy reference" link
(Wikipedia article, else OpenStax chapter).

Quiz engine (modal): question types and generators in `features/quiz/`.

- `find`: "Click the {name} on the model." Correct when the clicked part's
  key matches; either side accepted. The modal collapses to a banner so the
  model is clickable; a "Show me" button after answering flies to it.
- `identify`: highlights a part in the viewer; four name options drawn from
  the same region; correct is its name.
- `fact`: "Which is the primary action of {name}?" from facts/lessons; three
  distractor actions from other muscles in the pool; never two options with
  identical text.
- `evidence`: hand-written bank of at least 12 questions on fascial claims
  and evidence literacy, each with an explanation and citation id.

Sets: `region:<id>` (8), `line:<id>` (6), `mixed`. Ten questions per set,
drawn from `quiz-pool.ts` (about 80 muscles and 40 bones at undergrad A&P
scope). Progress in localStorage under `form.progress.v1`: per-key attempts
and correct counts, last-seen date. Start screen shows overall accuracy and
"weak spots" (accuracy under 60 percent with at least two attempts) with a
"Practice weak spots" set and a clear-progress button. Immediate feedback
with explanation after every answer.

Compare mode: "Pin" in the detail panel adds the selected id to `pinned`
(max 4, oldest dropped). Pinned parts render in four fixed distinct colors
and stay visible regardless of mode, hidden list, or isolation. A legend
strip over the viewer lists pins with remove buttons and "Clear pins".

Offline mode: `vite-plugin-pwa` (generateSW, autoUpdate). Precache the app
shell, CSS, JS, icons, and Draco decoder. Runtime CacheFirst for `body.glb`
(one entry, one-year expiry) so first paint is not blocked by an 8 MB
precache. Web app manifest with name, short name "Form", icons, theme color.
A one-time toast "Available offline" after the model is cached.

### 3.10 Error handling

- WebGL unavailable: existing fallback text stays; library, facts, fascia
  panel, research digest, and quiz `fact`/`evidence` types still work;
  `find`/`identify` sets are disabled with a message.
- Model load failure: existing retry button stays.
- URL decode: invalid values are ignored individually, never throw.
- Facts missing for a structure: rows omitted, no placeholder text.
- Clipboard write failure: toast shows the URL to copy manually.
- Citation verification failure: CI fails with the offending id.

### 3.11 Testing

Vitest, run in CI and locally with `npm test`:

- catalog: 826 parts, unique ids, every part has region and layer, spot
  checks (for example gastrocnemius -> leg-foot, latissimus dorsi -> back,
  deltoid -> shoulder-arm, soleus -> deep, deltoid -> superficial).
- urlCodec: encode/decode round trip for a full state; junk input yields
  defaults.
- appearance: selected, chain, pinned, hidden, isolated, opacity cases.
- regions: rule order and geometry fallback.
- quiz generators: correct option present, no duplicate options, side-
  agnostic `find` matching, seeded determinism.
- paths: point ordering and side switching for a crossing line.
- lines/research data: every citation id referenced exists; every stop key
  exists in the catalog or is null with a waypoint.
- GLB integrity test kept from Codex's suite (header, 826 parts, named
  structures, Draco views, WASM magic).

`npm run verify:citations` is a separate networked script run in CI.
Manual browser check after each phase: model renders, click-select, fascia
highlight, mobile layout at 375 px.

## 4. Phases

Each phase is its own implementation plan, lands on main, and deploys.

  react-server-dom-webpack); add vitest.

  side control arrives in phase 2.

- Create the public repo, push, add `.github/workflows/deploy.yml`
  (push to main: install, test, build, deploy-pages; pull requests: install,

## 7. Phase 5 addendum (approved 2026-09-07): arm chains, Latin names, playlists, bundle split

### 7.1 Arm chains

Three upper-limb lines from Wilke & Krause 2019 (Clin Anat, PMID 31226229),
grouped separately from the six body lines in the line list:

| id | name | stops (catalog keys) | studies |
| --- | --- | --- | --- |
| val | Ventral arm chain | pectoralis major -> biceps brachii (with brachial fascia, not modeled) -> forearm flexors, brachioradialis, supinator | 5 |
| lal | Lateral arm chain | trapezius -> deltoid -> brachialis (with lateral intermuscular septum, not modeled) -> brachioradialis | 4 |
| dal | Dorsal arm chain | latissimus dorsi, teres minor, infraspinatus -> triceps brachii -> anconeus -> extensor carpi ulnaris | 6 |

The review's abstract reports each chain and its study count but no hop-level
figures. Hops therefore carry a new status `chain-reported` whose badge reads
"Chain reported · N studies" with the note that hop-level counts are not
available from the abstract. Line grade `reported`. No force-transfer note.
`Line.group` is `"body"` or `"arm"`; tours, cables, deep links and quiz line
sets work unchanged. Three evidence questions cover the chains.

### 7.2 Latin names

`fetch-facts.ts` adds a Wikidata pass (batches of 50 titles,
`wbgetentities` with `languages=la`) and stores `latin` on each facts entry.
Wikidata labels are CC0. A store preference `names: "english" | "latin"`
(persisted in `localStorage` `form.names.v1`, not in the URL) switches the
primary label in the library and the detail title; the other language shows
as the secondary line so sub-part detail such as "lateral head" is never lost.
Search matches either language. Quiz prompts stay in English. Parts without a
Latin label fall back to English.

### 7.3 Teacher playlists

`playlist: { title, ids (max 30), step | null }` in the store, encoded as
`pl=<ids>` and `plt=<title, max 80 chars>`. "Add to playlist" in the detail
panel builds it in click order; a floating card over the stage lists the items
with remove buttons, a title field, Play / Previous / Next / Stop, Copy link
and Clear. Playing a step selects the part and flies to it; arrow keys step,
Escape stops. No accounts, no server: the URL is the playlist.

### 7.4 Bundle split

Three.js is emitted as its own chunk so the app shell parses before the 3D
library finishes downloading. No behaviour change.

## 8. Phase 6 addendum: study tools (2026-09-07)

Phase 5 made the atlas shareable. Phase 6 makes it a study tool: curated
sets to work through, exam-style innervation questions, a printable handout,

### 8.1 Study sets

## 11. Phase 9 addendum: motion and beauty (2026-09-07)

The model has no rig, so muscles cannot contract as meshes. Everything
below is either rendering quality, camera choreography, or rigid motion of
the skeleton with muscle lines of action drawn as cables. Each animated
element states what it approximates.

### 11.1 Rendering polish

- Image-based lighting from a room environment (PMREM) with reduced direct
  lights; materials keep their colours but gain soft reflections.
- A soft contact shadow under the feet grounds the figure.
- Every appearance change tweens: colour, emissive and opacity ease over
  about 250 ms; hiding fades out before the mesh is removed, showing fades
  in. Hover adds a gentle emissive lift. The selected part gets a thin
  back-face halo.
- Reduced motion: when `prefers-reduced-motion` is set, tweens snap, auto
  rotation and particle flow are off.

### 11.2 Cinematic line tours

- While a tour is playing, the camera drifts slowly around the current stop
  (OrbitControls auto-rotate), a caption band at the bottom of the stage
  names the stop, the next hop and its evidence badge, and the stage shows a
  soft vignette. Pausing or interacting stops the drift.

### 11.3 Pull direction

- When attachments are shown for a selected muscle, the engine draws a
  line of action from the insertion bone through the muscle to the origin
  bone, with particles flowing insertion to origin and an arrowhead at the
  origin, plus two labels: "Origin, fixed end" and "Insertion, moving end".
  Endpoints are the bone-mesh vertices nearest the muscle, so they are
  approximate; the panel says so.

### 11.4 Joint motion

- `src/data/motion.ts` derives, for a joint and side: the pivot (an
  extreme of the proximal bone's bounding box facing the distal bone), the
  flexion axis (mediolateral), the range, the moving set (distal bones plus
  muscles whose attachments are all distal, or whose centroid lies distal to
  the pivot plane when unmatched), and the crossing muscles with their cable
  endpoints.
- The engine rotates the moving set rigidly about the pivot. Crossing
  muscles are hidden and replaced by cables from origin to insertion; the
  insertion end moves with the segment. A cable that shortens through the
  motion is red, one that lengthens is blue, so agonists and antagonists
  read at a glance and the list appears in a motion card with a scrubber,
  play and pause, and a side toggle.
- Tests pin the elbow (biceps and brachialis shorten, triceps lengthens),
  the knee (hamstrings shorten, quadriceps lengthen) and the ankle.
- Caveat in the card: "Rigid rotation about an estimated joint centre;
  attachment points are approximate; real joints roll and glide."
- Store `motion: { joint; side; phase; playing } | null`; not in the URL.

## 12. Phase 10 addendum: mesh-accurate geometry and muscle deformation (2026-09-07)

### 12.1 Geometry from the mesh, not the box

- `scripts/build-geometry.ts` decodes the Draco geometry of every part with
  the `draco3d` Node decoder (header parsing as in `build-catalog.ts`) and
  writes `src/data/geometry.json`:
  - `pivots`: per joint and side, a joint centre from bone landmarks: the
    midpoint of the humeral epicondyles (elbow) and femoral condyles (knee),
    the femoral and humeral head centres (hip, shoulder), the midpoint of the
    malleoli (ankle), the midpoint of the distal radius and ulna (wrist), and
    the mandibular condyles (jaw). Landmarks are centroids or extremes of the
    top or bottom few percent of a bone's vertices.
  - `contacts`: for every muscle part and each bone its attachments name, the
    bone-surface vertex nearest the muscle (sampled vertices, so within a few
    millimetres).
- `src/data/geometry.ts` exposes `jointPivot(joint, side)` and
  `contact(muscleId, boneId)`; `motion.ts` and `pull.ts` use them and fall
  back to the bounding-box estimates when an entry is missing. The build runs
  offline from the committed GLB; the JSON is committed like the catalog.
- Tests: pivots exist for every joint and side and sit between the bones
  they join; contacts exist for at least 95% of attachment pairs; the
  classifications in the motion tests still hold and the deep head of
  pronator teres shortens at the elbow.

### 12.2 Muscles that bend, shorten and bulge

- In a joint motion, a crossing muscle is no longer hidden. The engine clones
  its geometry into a SkinnedMesh with two bones, a fixed root and the moving
  segment, and gives each vertex a weight from a smooth band across the joint
  plane, so the mesh bends at the joint and its ends follow the bones.
- A volume-preserving bulge in the vertex shader scales the mesh around its
  own axis by the inverse square root of its length ratio: a shortening
  muscle thickens, a lengthening one thins. The bulge is capped.
- The deformed copy mirrors the original's colour, emissive and opacity every
  frame so selection and hover still read; it is pickable.
- Lines of action stay available as a toggle in the motion card, off by
  default now that the muscle itself shows the change.
- With attachments shown, the selected muscle plays a slow contraction
  pulse: it shortens a few percent along its line of action toward the
  belly and bulges to match, then relaxes.
- Caveats in the card and panel: "Procedural deformation for teaching: the
  mesh bends and bulges by geometry, not by measured tissue mechanics."
- Reduced motion disables the pulse; the joint scrubber still deforms.

## 15. Phase 13 addendum: graphics, tiers A and B (2026-09-08)

Chase: "upgrade the graphics in its entirety … tier A and full tier B, I
want this to look great." Tier C (a higher-resolution model) stays on hold
until pilot students ask for finer shapes.

### 15.1 Quality levels

- A graphics preference, Auto · High · Low, in the left-panel foot, stored in
  `localStorage` `form.graphics.v1`, not in the URL (`?gfx=high|low` is a
  testing override). Low is the renderer as shipped in phase 12: forward
  rendering, no post-processing, pixel ratio up to 2. High adds everything
  below at pixel ratio up to 1.5.
- Auto picks High unless the system prefers reduced motion, the pointer is
  coarse and the viewport narrow (a phone), the GPU reports a software
  renderer, or the device has fewer than four cores or under 4 GB. After the
  model loads, Auto also meters the first three seconds of frames and drops
  to Low with a toast if the average frame exceeds 28 ms.

### 15.2 Tier A: materials and light (High)

- Post-processing chain: render, ground-truth ambient occlusion (GTAO,
  radius 0.25 model units, blend 0.9), bloom (threshold 1.0, strength 0.35,
  radius 0.4; only HDR-bright pixels bloom, which is the selection halo at
  twice brightness), output (ACES, sRGB), a grade pass (vignette, mild
  contrast and saturation, alpha preserved so the CSS stage shows through)
  and SMAA anti-aliasing. The bloom composite keeps alpha so glow over the
  empty stage has no dark fringe.
- Tissue materials: muscles become physical materials with sheen and a
  light clearcoat, fibre striations bumped along each muscle's principal
  axis in its own shader (amplitude 0.35, spacing about 3.5 mm), and a ±3 %
  tint by id so the mass does not read as one plastic. Bones: roughness
  0.62, warm. Connective parts: glossy, roughness 0.3, pale. Low keeps the
  standard materials.
- Shadows: the key light casts a 2048 px soft shadow onto a shadow-catching
  floor and onto the body; the shadow map re-renders only when appearance
  or pose changes, not on camera moves.
- Selection: the cyan halo is written at HDR brightness so it blooms into a
  soft glow; the mesh tint stays as in phase 12.

### 15.3 Tier B: cinematics (High)

- Tours: depth of field (bokeh) focused on the stop while the tour plays, a
  slow dolly from 1.08× to 1.0× of the framing distance over each stop, and
  a stronger vignette in cinematic.
- Floor reflection: a mirror plane under the feet rendered at 512 px, faded
  with distance from the contact and tinted to the slate; it re-renders only
  when the camera or appearance changes.

### 15.4 Verification

- Headless SwiftShader renders at 1440×900 (home, a selection, a tour stop,
  the knee motion) at High and Low; frame times in real Chrome at High and
  Low; the contrast check, the test suite and the a11y test pass; live
